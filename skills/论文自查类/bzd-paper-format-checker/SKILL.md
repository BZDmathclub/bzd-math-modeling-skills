# BZD Paper Format Checker

检查整篇数学建模论文的摘要可独立阅读性、页面结构、排版规范、篇幅分配、图表表达、建模表述可核验性、参考文献、匿名性和文件卫生。用户通常只需提供完整 PDF；若同时提供 Word，可进一步检查样式、隐藏批注、修订记录和文档属性。

## 平台兼容性

本技能的权威入口是本文件及 `references/` 中的 Markdown 规则，可直接用于 Codex、Claude、ChatGPT 或其他能够读取本地 Markdown 指令的智能体环境。不要依赖某个产品专属的工具调用、文件引用语法或内置表格功能；根据当前环境可用能力完成 PDF/Word 的提取与渲染。`agents/openai.yaml` 仅为 Codex/OpenAI 界面提供可选展示信息，其他平台可忽略它。

本 Skill 是独立的论文格式自查工具，不调用摘要、问题分析、模型假设或模型求解等章节内容 Skill，也不评价模型本身是否正确。执行检查前，必须完整阅读 [references/format-review-rules.md](references/format-review-rules.md) 与 [references/paper-section-self-check-table.md](references/paper-section-self-check-table.md)。评审时以自查表为逐项记录框架；涉及各问题、各模型、各段落、各图表和各公式的动态项目，必须按论文实际数量展开，不得以少量抽样代替全文核查。

检查结果默认直接在聊天框输出；用户明确要求保存时，输出单个 Markdown 报告文件。用户要求自行填写、打印或团队协作自查时，直接提供 [assets/数学建模论文自查表.xlsx](assets/数学建模论文自查表.xlsx)，不得重新生成不同版本。该单Sheet工作簿及 [references/paper-section-self-check-table.md](references/paper-section-self-check-table.md) 中的编号检查项是本 Skill 的权威检查清单；两者冲突时以工作簿为准。

## 规则优先级

1. 用户提供的当届竞赛官方规范；
2. 可从论文或模板直接确认的版式要求；
3. 本 Skill 中标明为“建议”的数学建模论文通用做法。

不得把通用建议冒充官方取消资格条款。无法确认竞赛类型或当届规则时，明确标记“按通用建议检查”。

## AI 使用材料边界

- 不要求在论文正文中设置“AI工具使用声明”。
- 若当届竞赛要求 AI 使用披露，只检查独立支撑材料是否存在、命名和匿名性是否合规。
- 未提供独立支撑材料时，不推断是否使用 AI，也不据此扣格式分；仅在已知官方要求且材料缺失时提示。

## 检查流程

1. 识别文件类型、总页数、摘要页、正文起始页、正文结束页和附录起始页。
2. 将摘要作为脱离赛题和正文的独立短文阅读，逐项核查问题、模型、求解、结果和结论；再检查摘要开头结构及页面长度。
3. 逐页渲染论文，核对摘要页数、页码、目录、页眉页脚、页面留白、图表清晰度和跨页情况。
4. 提取正文标题结构，检查标题层级、编号连续性、标题密度和各问题对应页数。二级标题通常每 1—1.5 页出现一次；多个二级标题间隔明显不足 1 页时扣分；每页三级标题不得超过 2 个，出现 3 个及以上时扣分；同时检查标题下是否具有实质内容。
5. 统计正文、主要问题求解、模型建立、求解过程、结果分析、图、表和大块留白的篇幅分布。
6. 对每一问检查“模型建立—模型求解—结果与解释”的篇幅平衡，识别某一问挤占全文或关键问过短。
7. 逐段阅读正文模型建立部分。检查每一段能否在不猜测的情况下理解，公式中的全部非通用符号是否已在符号表或正文首次出现处定义。
8. 对每个优化模型检查是否在推导后出现“综上所述，模型为”或完全等价的明确总结句，并紧接完整的目标函数、约束条件和变量域公式。
9. 检查正文文本的字体、字号、行距、缩进以及图题、表题、编号、三线表、公式和标点。
10. 检查图表是否由正文引出并解释。逐对比较图与表的数据对象、维度和数值；表达相同数据或相同结论即判为重复，不以“图看趋势、表看数值”为由自动放行。
11. 检查是否出现图片或表格堆积，并检查图内标题与正文图题的重复。坐标轴名称、图例和必要子图标题不属于重复。
12. 扫描正文、页眉页脚、文件名、路径、图表、截图和可读取元数据中的身份信息。
13. 双向核对正文引文与文末参考文献，核验可疑条目的作者、题名、DOI、期刊、页码、网址、访问日期和数据发布机构。
14. 检查数据预处理、算法求解、模型检验、灵敏度分析、跨问题联动和模型评价中的陈述是否有正文证据；只判断表达是否完整、前后一致和可核验，不代替模型正确性评价。
15. 对参考文件中的每一个原子检查点逐条输出结论和证据，再计算唯一、可复算的规范分。

## 高教社杯全国大学生数学建模竞赛特别规则

当用户明确说明论文参加“高教社杯全国大学生数学建模竞赛”或“国赛”时，适用以下规则：

- 论文中严禁出现目录。发现目录时，按官方资格或严重格式风险报告；未发现目录时，只写“未发现目录，符合该项要求”，不得因页数较长而建议添加目录。
- 不得仅因为 PDF 总页数、附录页数或代码页数较多，就认定“代码篇幅违规”“超页违规”或“资格风险”。只有用户提供的当届官方条款明确限制相关内容，或代码确实混入正文并造成可见的阅读、分页或信息堆积问题，才作相应判断。
- 代码、长表和原始输出可作为附录或独立支撑材料。是否保留在论文 PDF、是否单独提交、以及是否计入页数，必须以当届官方要求为准；缺少要求时标记“待核对官方规则”，不扣分、不虚构风险。
- 正文以约 30 页为建议目标，实际页数应服从当届官方限制和题目复杂度；不因不足或略高于 30 页自动扣分。
- 附录应按功能分板块，例如“支撑材料清单、软件环境、核心代码、补充结果”。完整代码宜控制在约 10 页，只保留支撑模型复现、数据处理、求解和检验的核心代码；通用工具函数、重复输出和可由文字/伪代码说明的实现细节宜放独立支撑材料。
- 上述正文、附录和代码篇幅是高质量写作建议，不是自动资格判定。只有实际挤占正文论证、形成难读的信息堆积，或违反用户提供的当届官方条款时，才指出问题并扣分。
- 不得把“模型检验必须3—5页”“必须删除全部代码”作为通用要求或修改建议。

## 输入与核验边界

| 输入 | 可以核验 | 不能可靠核验 |
|---|---|---|
| 仅 PDF | 页面结构、可见排版、页码、图表、公式、可见匿名信息及部分 PDF 元数据 | Word 隐藏批注、修订记录、源样式名称 |
| Word | 样式、字体字号、段落、批注、修订和文档属性；渲染后核对页面 | 导出后的最终 PDF 是否完全一致 |
| PDF + Word | 内容与版式交叉核对、元数据与隐藏内容检查 | 未提供的外部支撑文件 |

“文本抽取未发现”不等于视觉上确定不存在。图表、字体、跨页和留白必须结合逐页渲染判断。

## 原子检查点与评分

规范质量满分为 **15 分**，采用逐项扣分制，最低限制为 **-9999 分**。

- 参考文件中每一个项目符号都是一个独立检查点，不得将多个检查点合并成一句“整体通过”；
- 每个检查点必须标为 `满足 / 不满足 / 部分满足 / 无法核验 / 不适用`；
- `不满足`：按影响扣 1 分或 2 分；
- `部分满足`：存在实质缺口时扣 1 分；仅属轻微优化时可以不扣，但必须说明；
- 核心信息缺失、系统性错误、严重影响阅读或可能违反明确规则时扣 2 分；
- 一般完整性、统一性、清晰度或局部规范问题扣 1 分；
- `无法核验` 与 `不适用` 不扣分，但必须说明缺少什么证据；
- 最终分数计算为 `15 - 所有原子检查点扣分合计`，允许为负数；计算结果低于 -9999 时按 -9999 计；
- 同一现象可以导致多个独立要求同时未满足，但若只是同一个排版模板错误在多页机械重复，不逐页无限重复扣分；
- 官方资格性问题另标 `资格风险`，不能被分数抵消。

例：摘要独立性包含5个独立检查点。缺少“求解方法”和“关键结果”时，应分别扣分，不能只写“摘要不完整，扣2分”。

所有 Markdown 表格必须有完整表头和分隔行，每行列数一致；不得输出“编号原子检查点状态证据扣分”或“目录未发现建议添加目录”这类粘连、矛盾或缺列的表格。仅输出已检查到的重点原子项与问题清单；若用户要求完整逐项记录，可在 Markdown 报告中附完整原子检查表。报告中每一项资格风险都必须同时写明：对应的官方条款来源、可观察证据和为何构成该风险。缺少任何一项时，等级只能为“待核对官方规则”或普通建议。

## 行为边界

- 不检查模型选型、数学推导或结果数值是否正确；但必须检查相关陈述是否有指标、参数、公式、图表、对照结果或前后文依据，是否存在虚构检验、伪联动或无依据评价。
- 目录、附录、代码、总页数和支撑材料的判断必须先识别竞赛类型。不得把其他竞赛的模板、个人偏好或“长文档惯例”套用于高教社杯国赛。
- 不得用“代码过长”“代码占比高”“42页长文档应有目录”等主观阈值直接扣分或判资格风险。
- 不因正文少于 30 页自动扣分；30 页是通常上限建议，不是必须写满的目标。
- 高教社杯场景以“正文约 30 页、附录分板块、核心代码约 10 页”为优先写作建议；应结合题量、难度和当届官方页数要求调整，不能将其改写为自动扣分阈值。
- 不机械要求每一问长度相同。篇幅应与任务难度、模型复杂度和评分权重相匹配。
- 不要求每个问题严格达到固定百分比；以“模型建立约 50%，求解过程约 20%—30%，结果与解释约 20%—30%”作为诊断参照，只有明显失衡并影响说明完整性时才提醒或扣分。
- 不以图表数量判断质量。图表必须有信息价值、有正文解释，并避免图片、表格或大段文字单一堆积。
- 图与表表达同一批信息时，应明确各自承担的不同作用；完全重复且无新增信息时提示精简。
- 不凭 PDF 文本抽取结果判断字体或图片清晰度；必须查看渲染页面。
- 只有 PDF 时，不得声称已经检查 Word 隐藏批注或修订记录。
- 不得因为总分已经低于 0 而停止检查；仍须完成全部原子检查点。
- 不得只抽查正文中少数公式。模型建立部分必须逐段阅读并建立符号定义追踪；同一未定义符号反复出现时按同一根因处理，但不同未定义符号分别检查。
