# nature-AIGC检测器整合指南
## 如何在bzd-paper-aigc-auditor中应用nature-detector的5大维度

---

## nature-detector的核心方法论

nature-AIGC检测器（原始设计用于学术论文）包含5个互补的检测维度：

| 维度 | 检测对象 | 检测时间 | 适用场景 |
|-----|--------|--------|--------|
| **1. 统计特征** | Zipf系数、句长分布、TTR、n-gram重复 | 快速(5m) | 初筛 |
| **2. 句级连贯性** | 因果链、代词指代、时间序列、情态动词 | 细致(10m) | 深查 |
| **3. 事实验证** | 引文、数值、常识、领域范围 | 深度(15m) | 确认 |
| **4. 上下文一致** | 内部矛盾、假说-方法-结果、术语 | 交叉(10m) | 交叉检查 |
| **5. 风格一致性** | 转折质量、段落凝聚力、术语一致 | 整体(8m) | 综合评估 |

---

## bzd-paper-aigc-auditor v2.1中的整合策略

### 核心整合：9维 = 6维语言 + 3维事实

```
原bzd框架（5维）             nature-detector（5维）          增强框架（9维）
├─ 语言模板化(60%)    +    ├─ 统计特征                ──>  ├─ 维1-6: 语言层面
│  ├─ 连接词              ├─ 句级连贯性                     │  ├─ 维1: 高频词
│  ├─ 排比同构              ├─ 事实验证      ✨ 新增      │  ├─ 维2: 排比
│  ├─ 拔高词             └─ 风格一致性                     │  ├─ 维3: 拔高词
│  ├─ 被动句                                              │  ├─ 维4: 被动句
│  └─ [无文本复杂度]                                       │  ├─ 维5: 段落规律
│                                                         │  └─ 维6: 文本复杂度
│
├─ 其他四维(40%)   ✨ 部分重构为事实层面              └─ 维7-9: 事实层面
│  ├─ 结构与论证                                         ├─ 维7: 引文验证
│  ├─ 建模专属性                                         ├─ 维8: 数值一致性
│  ├─ 求解与验证                                        └─ 维9: 术语一致性
│  └─ 来源与一致性
```

## 1. 统计特征分析 → 维度1-6的支撑

### 1.1 Zipf系数（词频分布）

**原理**：词频f ∝ rank^(-α)
```
正常学术文本：α ∈ [1.0, 1.5]
AI文本：α < 0.8（词汇过于均匀）或 α > 2.0（高频词重复过多）
```

**在数学建模中的应用**：
```
数模竞赛论文的AI特征：
- α < 0.8 → "本文""采用""利用"等高频词占比>30%
- α > 2.0 → 某几个词（如"模型""方法""优化"）严重重复

检查方法（定性）：
列出前30个最高频词的出现次数
观察是否有词频分布不自然（几个词占绝对主导）
```

### 1.2 句长分布σ（标准差）

**标准**：
```
正常文本：σ ≈ 8-12字（自然波动）
AI文本：σ < 3字（规律过高）

计算方法：
抽取100句，逐个统计字数
计算字数的标准差
```

**数学建模应用**：
```
好的论文：
"模型采用二分搜索。" (6字)
"对于224个离散位置的搜索，相比蛮力搜索O(n²)的时间复杂度O(n²)，
 二分搜索O(log n)可以在10倍以上的效率提升。" (60字)
"因此选择二分搜索。" (8字)
→ 长度分布6-60-8，自然波动

AI生成的风险：
"采用二分搜索进行求解。" (12字)
"采用改进的二分搜索进行优化。" (14字)
"采用混合的二分搜索进行加速。" (15字)
→ 长度分布12-14-15，过于规律
```

### 1.3 TTR（词汇多样性）

**计算**：TTR = 不同词数 / 总词数

**标准**：
```
>0.6      正常（词汇丰富）
0.5-0.6   正常
0.4-0.5   轻微警戒
<0.4      高风险（词汇过度重复）
```

**数学建模应用**：
```
抽取论文全文或代表章节
统计不同词数和总词数
AI特征：TTR < 0.4（同样的词反复使用）
```

### 1.4 3-gram/4-gram重复率

**检查**：相同的短语组合出现>3次

```
高风险示例：
"本文采用..." 出现5次
"通过...方法..." 出现6次
"采用...算法..." 出现4次
→ 3-gram重复率 = 15/total，>10%为严重

低风险示例：
短语表述多样化，每个独特短语<3次
```

## 2. 句级连贯性 → 维度4-5的深化

### 2.1 因果链完整性

**AI特征**：断裂的因果链
```
❌ 问题分析：模型选择...
   求解方法：结果显示...
   结果分析：改进明显
   → "模型选择" 到 "改进"之间的因果关系不明确
```

**正常特征**：完整的因果链
```
✓ Q1模型选择了SAT算法
  原因：该算法具有O(n)复杂度
  
  Q2求解：利用SAT的O(n)复杂度在224个对象上完成搜索
  结果：耗时<0.1s
  
  Q3灵敏度：参数±10%时结果偏差<1%
  结论：SAT算法选择合理，求解鲁棒
  → 因果链：选择→原因→求解→验证→结论
```

**检查方法**：
- 每个结论前面是否都有推导过程？
- 是否存在"为什么"被跳过的现象？
- 跨问间是否有明确的"因"（前问的结果）和"果"（当前问的应用）？

### 2.2 代词指代清晰度

**AI特征**：代词过多且指代模糊
```
❌ "该模型...该方法...它...其特性...这样设计..."
   → 5个代词在2句话内，指代不清
```

**正常特征**：明确指代和术语重复混合
```
✓ "SAT碰撞检测算法...该算法通过分离轴定理...
   SAT的性能优势在于O(n)复杂度..."
   → 直接用术语名称，不滥用代词
```

## 3. 事实验证 → 维度7-9的基础

### 3.1 引文验证工作流

**nature-detector的三层模型**：

#### L1: 格式检查（30秒，快速筛选）
```
✓ DOI格式：10.XXXXX/...
✓ 作者名：Lastname, Firstname Initial
✓ 期刊名：正确拼写、大小写
✓ 年份：通常不超过20年（除非经典）

风险信号：
✗ DOI不规范 → 虚构可能性高
✗ 作者名非标准 → 可能伪造
✗ 期刊名拼写错误 → 可能幻觉
```

#### L2: 存在性验证（2-3分钟，确认真实性）
```
检查途径：
1. Google Scholar: scholar.google.com
2. 知网: cnki.net (中文论文)
3. 期刊官网或PubMed

验证内容：
✓ 文献是否存在？
✓ 作者、题名、年份是否完全匹配？
✓ DOI是否正确映射？

高风险信号：
✗ 无法找到 → 虚构可能性极高（即判定为幻觉）
✗ 题名部分不匹配 → 伪造或严重错误
```

#### L3: 主张-支撑匹配（5分钟，仅抽查关键文献）
```
检查内容：
1. "根据XXX文献，我们采用..." 
   → 查该文献，是否真的提出了这个方法？
   
2. "使用XXX数据集"
   → 验证数据集是否存在、规模是否一致
   
3. "按照XXX的方法论"
   → 抽查该文献，方法描述是否与论文一致

高风险信号：
✗ 文献中主张与论文引用不符
✗ 数据集规模虚报
✗ "改进XXX"但无具体改进说明
```

**数学建模特化检查**：
```
重点验证对象：
- 竞赛常见算法的论文（如ARIMA、K-means、遗传算法等）
- "改进的XXX"论文（确认改进是否有实质）
- 数据集论文（规模、领域是否与赛题匹配）

提示：
如果引文都是"综述文献""教科书"，而没有具体算法论文，
可能表明论文作者对算法理论不够深入（AI特征之一）
```

### 3.2 数值一致性检查

**nature-detector的逻辑**：AI最容易在"重复使用历史数据"时出错
- 数据来自LLM的训练集，而非实际计算
- 前后使用同一数值的不同版本

**在数学建模中的应用**：
```
构建参数追踪表：
┌────────┬─────────┬─────────┬─────────────┐
│参数    │首次出现 │P值      │使用位置     │一致性│
├────────┼─────────┼─────────┼─────────────┤
│p=0.55m │P1表1   │0.55m    │P3,P8,表2..  │✓    │
│v=1m/s  │P2推导   │1.0m/s   │P5,公式(3).. │✓    │
│Δt=0.5s │P6设定   │0.5s     │表3,代码行.. │△±1% │
└────────┴─────────┴─────────┴─────────────┘

判分标准：
✓ 完全一致         → 100分
△ 轻微波动(±1%)   → 70分（可能舍入或单位转换）
✗ 明显矛盾(>5%)   → 0分（虚构或计算错误）
```

### 3.3 常识性检查（领域特定）

**数学建模竞赛的常识**：
```
赛题规模常识：
✓ 通常5-7个问题（不会1-2个或10+个）
✓ 数据规模通常百到千的量级（224把手、1600人等）
✓ 参考文献通常8-15篇（<5篇显得论证不足，>25篇显得堆砌）

模型选择常识：
✓ 小规模问题(n<1000)用复杂模型(深度学习)为不合理
✓ 为什么问题1和问题2使用完全不同的模型？（应有递进关系）
✓ 参数调优是否有明确的必要性说明？
```

## 4. 上下文一致性 → 维度9的核心

### 4.1 内部矛盾检测

**nature-detector的方法**：扫描全文，找"A和¬A"的表述

**数学建模中的应用**：
```
高风险矛盾：
P1: "采用遗传算法GA进行路径优化"
P5: "利用进化策略ES进行多目标求解"
P10: "该种群智能算法的优势在于..."
→ 到底用的是GA、ES还是其他？概念混乱

另一种矛盾：
问题分析："需要在最短时间内完成运输"
求解过程："采用贪心算法快速求解，耗时<0.1s"
灵敏度分析："当耗时要求增加至1s时，方案改变为..."
→ 时间要求的定义前后不一
```

### 4.2 假说-方法-结果对齐

**AI特征**：假说和结果逻辑不匹配
```
❌ 假说："直升机燃油成本占总成本60%"
   方法："因此采用深度学习"
   结果："精度99.5%"
   → 假说关于燃油，方法和结果关于精度，逻辑割裂
```

**正常对齐**：
```
✓ 假说："多设施联合运输能减少往返"
  方法："建立混合优化模型，比较单架次vs多架次"
  结果："多架次方案运次减少25%，燃油节省35%"
  → 假说、方法、结果完全对齐
```

### 4.3 术语一致性

**nature-detector的观察**：AI常见"换词"现象
```
❌ 前文用"遗传算法"，中文用"进化策略"，后文用"种群搜索"
   → 显得概念混乱，不像来自同一个大脑
```

**检查方法**：构建术语追踪表
```
┌──────────┬──────┬──────┬──────┬──────────┐
│核心术语  │P1   │P5    │P10   │一致性    │
├──────────┼──────┼──────┼──────┼──────────┤
│算法      │GA   │GA    │GA    │✓一致    │
│运次数    │运次  │班次  │运次  │△混用    │
│多架次    │多设施│多架次│联合  │🔴混乱   │
└──────────┴──────┴──────┴──────┴──────────┘
```

## 5. 风格一致性 → 综合判断

### 5.1 转折质量

**AI特征**：转折词不自然
```
❌ "采用遗传算法进行优化。然而，(...补充说明...)"
   → "然而"后应该接对比或相反内容，但实际是补充说明，逻辑不通
```

**正常**：
```
✓ "采用遗传算法以快速搜索。但为了保证最优性，
   我们还加入了本地搜索模块以避免陷入局部最优。"
   → "但"正确地表达了思路的调整
```

### 5.2 段落凝聚力

**AI特征**：段落像独立的"模块"拼接
```
❌ 每段都能单独成文，段与段之间无逻辑承接
   没有"由上文可知""基于此""相比之下"这样的承接词
```

**正常**：
```
✓ 段落间有自然的承接
  段尾：...因此本题需要混合优化方法
  段首：针对此需求，我们设计了DP-ILS混合框架...
```

## 6. 综合应用流程

### 快速检查流程（5分钟）
```
Step1: 统计特征快速扫描
  □ TTR是否>0.5？(用Ctrl+F查询高频词)
  □ 被动句占比是否<30%？(抽查2段)
  □ 3-gram重复是否<10%？(观察关键短语)
  
  → 3个都通过 → 可速判为"低-中风险"
  → 有1个不通过 → 进入详查
```

### 详细检查流程（15分钟）
```
Step2: 因果链&术语追踪
  □ 每个问间都有"因"(前问结果)吗？
  □ 算法术语是否始终一致？
  
Step3: 引文&数值验证
  □ 抽查3篇关键引文（L1-L3检查）
  □ 追踪5个关键参数，是否始终一致？
  
Step4: 内部矛盾检测
  □ 是否存在"A和¬A"的表述？
  □ 假说-方法-结果是否对齐？
```

## 7. 修改建议参考

当发现nature-detector的五大维度中有问题时：

| 维度 | 问题信号 | 改进方向 |
|-----|--------|--------|
| **统计特征** | TTR<0.4 / 句长σ<3 | 增加词汇多样性、调整句长分布 |
| **句级连贯性** | 因果链断裂 / 代词过多 | 补充推导过程、减少代词使用 |
| **事实验证** | 引文找不到 / 数值矛盾 | 核实引文信息、检查数值一致性 |
| **上下文一致** | 术语混乱 / 矛盾表述 | 统一术语、调整逻辑 |
| **风格一致** | 段落割裂 / 转折不当 | 补充承接词、调整段落结构 |
