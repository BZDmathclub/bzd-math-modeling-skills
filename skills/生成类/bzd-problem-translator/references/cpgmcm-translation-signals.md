# 华为杯研究生赛题意翻译信号库

## 使用顺序与边界

先按 [cpgmcm-plain-language-translation.md](cpgmcm-plain-language-translation.md) 完成降维理解层，再逐句读取当前题目，然后参考本文件追问「这句话是否承担了类似作用」。

本文件归纳的是华为杯题目的**结构性特征**，不是分题号的固定内核。华为杯题号与题型的对应关系不稳定（同一字母在不同年份可能是完全不同的学科方向），因此**不得按题号预设题型**。识别特征应当来自题面本身。

历史规律只用于生成追问，不得补写题面没有的条件。

## 与国赛的关键差异

| 维度 | 国赛 CUMCM | 华为杯 CPGMCM |
|---|---|---|
| 题面来源 | 命题人为竞赛设计，已做教学化处理 | 常直接来自企业课题或科研项目 |
| 主要难点 | 建模与求解的完成度 | **读懂题目本身** |
| 术语密度 | 中等，多数有题内定义 | 高，大量术语默认选手已知 |
| 背景假设 | 基本自洽 | 默认具备领域背景知识 |
| 题面质量 | 打磨充分 | 可能存在表述冗余、局部歧义、前后措辞不一 |
| 小问数量 | 多为 3—4 问 | 常见 4—5 问，跨度更大 |
| 数据附件 | 结构相对干净 | 常为实测数据，含噪声、缺失、异常 |

因此华为杯的翻译重心前移：**先降维建立直觉，再逐句精确对齐**。这与国赛只做逐句翻译的流程不同。

## 题面质量问题的处理

华为杯题面打磨程度不如国赛，可能出现：

- 同一概念前后用词不一致（如前文「损耗」后文「能耗」）；
- 冗余叙述掩盖真正约束；
- 小问表述与背景描述的口径不完全吻合；
- 附件字段名与正文术语对不上；
- 精度或输出格式要求只在某一处提过一次。

处理原则：

1. **如实标注，不擅自统一**。发现措辞不一致时，在术语口径表中并列两种说法，标明各自出现位置，给出建议采用的口径及理由。不要悄悄改成一种。
2. **区分冗余与约束**。看似背景的句子可能藏着唯一一次出现的硬要求。凡涉及数值、方向、信息来源、输出格式的句子，一律按约束处理。
3. **歧义列后果**。对影响结果的歧义，列出各种解释及其导致的不同结论，建议做情景或敏感性处理，不替选手拍板。
4. **附件与正文对账**。逐一核对附件字段与正文术语的对应关系，对不上的显式列出。

## 常见结构内核

按题面实际特征匹配，不按题号：

| 结构内核 | 识别特征 | 题干信号应翻译成什么 |
|---|---|---|
| 机理建模—参数辨识 | 给出物理/化学/生物过程描述与实测数据，要求反推参数或补正经验公式 | 经验公式→待修正基线；实测数据→辨识依据与误差来源；工况范围→外推边界；「修正」→必须给出显式修正式与系数估计 |
| 工程优化—多目标权衡 | 存在可调设计变量、多个相互冲突的指标、明确可行域 | 指标冲突→多目标而非加权单目标；工艺限制→硬约束；「兼顾」→需给出权衡前沿或明确取舍理由 |
| 信号—时空延迟 | 涉及传播、时标、坐标系、观测位置变化 | 坐标系名称→必须换算；时标名称→时间定义不同；「忽略」→显式假设边界；量级提示→精度要求 |
| 数据驱动—识别预测 | 提供带标签或多工况数据集，要求分类、预测或跨工况泛化 | 字段名→物理含义；时间戳→预测时可用信息边界；同主体多记录→分组划分要求；「跨工况」→不得用目标工况信息 |
| 规则调度—可执行方案 | 密集业务规则、资源容量、时序事件 | 优先级→非普通加权；容量时窗→资源约束；「一般模型」→参数化表达；结果文件→逐对象逐时操作表 |
| 不确定性—风险决策 | 含随机性、可靠性指标、极端情形 | 概率措辞→分布假设需依据；可靠度数值→硬指标；「极端」→需给出边界工况定义 |

一道题可能同时含多个内核，尤其小问之间切换内核。逐问判断，不要整题套一个。

## 跨问联动的典型结构

华为杯常见递进模式：

- **认识 → 基础模型 → 增加复杂度 → 优化或决策 → 部署/极限验证**；
- **单工况 → 多工况 → 跨工况外推**；
- **正问题（已知参数算结果）→ 反问题（已知结果推参数）**；
- **确定性 → 引入不确定性 → 风险约束下重新决策**。

只有当前题目真实支持时才画上述链；平行小问必须画成平行分支。

## 高风险漏读提示

- 术语在题面中只定义过一次，后文换了说法，导致口径漂移；
- 附件某列的单位与正文不同（如正文用 mm、附件用 m）；
- 「不考虑」、「假设忽略」限定了模型边界，却被当作可选简化；
- 跨工况预测时偷用了目标工况的信息；
- 精度、有效位数、输出文件格式要求只在题面某个角落出现过一次；
- 小问要求「给出方案」却只提交了指标数值；
- 实测数据的噪声、缺失、异常未做处理即直接建模；
- 把题面的工程动机当作可弃背景，遗漏了它设定的目标优先级。

每条内部记录可标注：`structural_kernel`、`signal`、`explicit_or_implied`、`implication`、`upstream`、`downstream`、`omission_risk`、`required_evidence`、`text_quality_issue`、`confidence`、`hard_rule`。
