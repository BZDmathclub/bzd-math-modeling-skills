# 华为杯研究生赛：小学应用题式题意还原

## 1. 为什么需要这一层

中国研究生数学建模竞赛（华为杯，CPGMCM）的题目难点不在数学深度，而在**进入成本**：题面往往来自真实工程或科研课题，篇幅长、专业名词密集、背景知识默认选手已具备。选手的第一道坎不是「不会建模」，而是「读完三页还不知道它到底要我算什么」。

因此对华为杯题目，在逐句精确翻译之前，必须先交付一次**降维理解**：把整题的背景与题干改写成一道小学或初中应用题，让选手在两分钟内抓住「谁、有什么、求什么」。

这一层的唯一目的是**建立正确的直觉**。它不是建模依据。

## 2. 触发条件

识别为华为杯题目时启用本层。可用信号（任一成立即可）：

- 用户明确说明是华为杯、研究生数模、中国研究生数学建模竞赛、CPGMCM；
- 题面出现 `中国研究生数学建模竞赛`、`全国研究生数学建模竞赛`、`华为杯`；
- 题号形如 `A题`—`F题` 且题面具备研究生赛特征：真实工程/科研课题背景、大段领域文献式叙述、附带实测数据附件、题干含未经解释的领域术语。

仅凭题号字母判断不足。若信号不充分，向用户确认一次：`这是华为杯（中国研究生数学建模竞赛）题目吗？`。确认前不要臆断赛事。

对非华为杯题目，本层默认不输出。用户明确要求时可对任何题目启用，但必须同样遵守本文件的全部约束。

## 3. 三条不可违背的底线

降维改写会丢失精度，这是它的固有代价。用下面三条把代价关在笼子里。

### 3.1 附加而非替代

小学应用题版**附加**在报告最前，绝不替代逐句翻译表。原题的数字、单位、区间、否定词、信息边界仍必须在逐句表中原样保留。删掉逐句表只留应用题版的报告是残缺的，不得交付。

### 3.2 强制回映射

每一个被简化的专业名词都必须在术语映射表中给出回路：`原文术语 → 生活化替身 → 这个替身丢掉了什么`。第三列是硬要求，不许写「无」。选手凭映射表可以从应用题版走回原文，反之亦然。

### 3.3 显式声明不可用于建模

应用题版正文之后必须紧跟一行固定提示：

> ⚠️ 本节是帮助理解的类比版本，已丢失精度，**不可作为建模与求解依据**。实际建模必须回到第 3 节逐句翻译表与原始题面。

不得省略、弱化或改写这句话。

## 4. 改写方法

### 4.1 先剥离，后重建

1. **剥离领域外衣**：去掉学科名词、文献引用、机理叙述、行业惯例，只留下数学骨架——有哪些对象、对象有哪些量、量之间有什么关系、要求哪个量。
2. **识别数学骨架类型**：是「已知若干条件求一个数」、「在限制下找最省/最多的方案」、「根据已有规律猜下一个」、「把一堆东西分类」、「从看到的结果倒推原因」，还是它们的组合。
3. **换一套日常外衣**：给骨架套上小学生熟悉的场景。场景必须与骨架**同构**，不是随便找个比喻。
4. **验算同构性**：应用题的解法步骤应当与原题的建模步骤一一对应。若应用题两步就能算完而原题要建五个模型，说明骨架抓错了，重做。

### 4.2 场景选材

优先选用这些选手童年就熟悉的场景：

| 数学骨架 | 可用日常场景 |
|---|---|
| 参数辨识 / 反演 | 猜盒子里有几颗糖、根据脚印猜身高、听声音猜远近 |
| 约束优化 | 零花钱买零食、书包装书、排队打水、拼图铺地板 |
| 时序预测 | 记录每天身高、猜明天气温、存钱罐攒钱 |
| 分类识别 | 按形状分积木、区分猫狗照片、挑出坏苹果 |
| 路径 / 调度 | 送快递跑几家、打扫教室分工、课程表排座位 |
| 信号 / 延迟 | 远处打雷先看到闪电后听到声、灯塔闪灯、回声测距 |
| 多主体协同 | 几个人合作搬桌子、接力赛交棒、分组做值日 |
| 状态切换 | 红绿灯变化、跳格子游戏、开关灯 |

同一道题的多个小问可以共用一个场景，用「第二天」、「换成三个人」、「如果老师又加了一条规则」串起来——这恰好对应原题小问间的递进关系。

### 4.3 语言标准

- 句子短，一句话一件事；
- 不用任何学科名词，包括看似通俗的（「频谱」、「协方差」、「泛化」都不行）；
- 数字尽量换成小而整的数（3 个、5 元、10 分钟），量级差异用「多得多 / 少得多」表达；
- 保留原题的**逻辑强度**词：只能、至少、最多、必须、不许、每一个。这些词决定问题性质，不许软化；
- 允许出现的最高数学工具：四则运算、比例、简单方程、平均数、面积体积、简单概率。超出就说明降维不够。

### 4.4 允许与不允许的简化

| 可以简化 | 必须保住 |
|---|---|
| 学科名词与机理细节 | 有几个待求量、要求哪个量 |
| 具体数值与单位 | 约束的方向（上限还是下限） |
| 数据规模与维度 | 小问之间的依赖顺序 |
| 精度与误差要求 | 「只能用某些信息」这类信息边界 |
| 文献背景与工程动机 | 目标是最大化还是最小化 |

右列任何一项在应用题版中失真，就是改写失败，必须重写。

## 5. 必须输出的四块内容

### 5.1 一句话版

不超过 40 字，回答「这题到底要算什么」。禁止出现任何专业名词。

### 5.2 小学应用题版

一段连贯的应用题，含场景、已知、限制、所求。每个小问对应应用题中的一问，编号与原题小问严格对齐。篇幅控制在 400 字内——写长了说明没抓住骨架。

紧跟 3.3 的固定警示行。

### 5.3 术语生活化映射表

| 原文专业术语 | 生活化替身 | 这个替身丢掉了什么 | 对应小问 |
|---|---|---|---|

覆盖题面中所有会阻碍理解的术语。第三列必填。

### 5.4 背景知识补课卡

针对题面默认选手已懂、实际多数人不懂的领域常识，每条三句话以内：这是什么、为什么题目需要它、不懂会在哪一问翻车。

| 需要补的背景 | 三句话说明 | 不懂会影响哪一问 |
|---|---|---|

没有需要补课的背景时写「无」，不要硬凑。

## 6. 完整示例

以 2024 年 F 题「X射线脉冲星光子到达时间建模」为例。

**一句话版**：远处有个按固定节奏闪光的灯塔，你在动，要算出闪光到你这儿的准确时刻。

**小学应用题版**：

> 操场很远的地方有一座灯塔，它每 2 秒闪一次灯，节奏非常准。小明坐在旋转木马上，木马绕着一根柱子转圈，柱子本身又被大人推着慢慢走。
>
> (1) 已知木马转一圈要多久、半径多长，还知道它现在转到哪个位置，求小明此刻离柱子多远、往哪个方向走、走得多快。
>
> (2) 因为小明一会儿离灯塔近一点、一会儿远一点，光走的路长短不同，他看到闪光的时刻就会忽早忽晚。假设光走直线且一路顺畅，求这个早晚差。
>
> (3) 实际上光路上还有一个大水坑（太阳），光经过水坑附近会走慢一点，而且小明的手表在转圈时走得也和地上的钟不完全一样。把这些都算进去，求更准的时刻。
>
> (4) 灯塔的闪光其实不是每次都亮得一样，有时一次飘来好几个亮点，有时一个都没有。请按前面算出的规律，编出一串"亮点分别在什么时刻到达"的假记录。

> ⚠️ 本节是帮助理解的类比版本，已丢失精度，**不可作为建模与求解依据**。实际建模必须回到第 3 节逐句翻译表与原始题面。

**术语映射（摘录）**：

| 原文专业术语 | 生活化替身 | 这个替身丢掉了什么 | 对应小问 |
|---|---|---|---|
| X射线脉冲星 | 每隔固定时间闪一次的灯塔 | 脉冲轮廓形状、能谱、自转缓变 | 全题 |
| 轨道六要素 | 木马转一圈的半径与当前转到哪 | 三维定向、偏心率、近点角的耦合 | (1) |
| GCRS / BCRS | 以柱子为原点 / 以操场中心为原点 | 相对论性坐标时定义与尺度因子 | (1)(2)(3) |
| 几何延迟（Roemer） | 离灯塔远近不同导致的看到时刻早晚 | 平行光假设、投影方向精度 | (2) |
| Shapiro 延迟 | 光过水坑附近走得慢 | 引力势积分与天体质量依赖 | (3) |
| TT—TDB 转换 | 转圈时手表和地上钟走得不一样 | 周期项量级与时标定义 | (3) |
| 光子到达时间序列 | 一串"亮点什么时候到"的记录 | 泊松到达统计与能量筛选 | (4) |

**背景补课卡（摘录）**：

| 需要补的背景 | 三句话说明 | 不懂会影响哪一问 |
|---|---|---|
| 为什么要换坐标系 | 航天器位置天然以地心为参考，而脉冲星方向以太阳系质心为参考。两套尺子不换算，算出的距离就不是同一条线段。换算误差会直接变成时间误差。 | (1)(2)(3) |
| 延迟为什么能有几百秒 | 光速虽快，但地球轨道直径约三亿公里。光穿过这段距离要十几分钟，所以观测位置不同造成的到达时刻差可以达到百秒量级。 | (2) |

这个示例说明改写的标准：**灯塔—旋转木马场景与原题四问的递进结构完全同构**，而映射表第三列老实交代了每一步简化的代价。

## 7. 自检

交付前逐条确认：

1. 一句话版不超过 40 字且零专业名词；
2. 应用题小问编号与原题小问一一对应，无遗漏、无合并、无新增；
3. 应用题的解题步骤数与原题建模步骤数量级相当；
4. 固定警示行原文出现，未被改写；
5. 术语映射表第三列无空缺、无「无」；
6. 4.4 右列五项在应用题版中全部未失真；
7. 应用题版中未出现任何学科名词；
8. 逐句精确翻译表仍然完整存在，未被本层替代。

任一项不通过，重写本层后再交付。
